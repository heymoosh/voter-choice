**Why the audit workflow is schedule-only, not blocking:** the Class C loop
table calls for "weekly; block merge on high severity." A baseline
`npm audit --audit-level=high` run on 2026-07-20 found **32 existing
advisories (12 high, 2 critical)** — vitest, `ws`, jsdom, puppeteer-core,
all dev/test tooling, no runtime-only deps flagged. Wiring this straight
into `pull_request` today would fail on every future PR from the first run,
which functions as a new gate on the merge flow rather than a scanner
addition — so it's scheduled (weekly + `workflow_dispatch`) and left off PRs
for now. Recommend: triage the 32 findings (mostly `npm audit fix`-able),
then promote the job to `pull_request` once the baseline is clean.
