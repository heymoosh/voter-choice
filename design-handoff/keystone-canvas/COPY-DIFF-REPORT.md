# Keystone copy-diff report — canvas vs. repo, per surface

**Date:** 2026-07-07 · **Phase:** 3 of `docs/operations/keystone-design-source-plan-2026-07.md` · **Companion:** `design-handoff/keystone-canvas/HANDOFF-EXACT-MATCH.md` §2 (the adjudication policy this report feeds)

## What this is

Per the plan's Phase 3 goal condition, this is a **report, not a change** — every row below is a place where the recovered canvas copy (`design-handoff/keystone-canvas/src/screens-*.jsx`) disagrees with the copy currently live in the repo. **No copy in this report ships until Muxin rules on it, item by item, in the "Muxin's ruling" column.**

**RULINGS RECORDED 2026-07-07 (Muxin, live).** Every row below now carries her verdict. A few rows still need a second pass — see the **OPEN ITEMS** callout at the end of each affected section — and are marked `NEEDS RULING` or `FLAG` inline. Nothing marked `NEEDS RULING` ships yet. Implementation (actually porting the ruled copy into the repo) is separate follow-up work, not done by this report.

Per HANDOFF-EXACT-MATCH.md §2 (superseded 2026-07-07 from a blanket "repo wins where more current" rule): the canvas copy is the **default** source of truth, but the repo has also moved since the canvas session, so **no version wins automatically** — an agent's judgment about which is "more current" is exactly the failure mode this process closes. Each row is annotated with when the repo string was last touched (date, and PR number where the commit message references one) so Muxin can weigh recency herself. Where a specific string's own history couldn't be isolated with `git log -S` (e.g. it has no repo counterpart at all, so there's nothing to search for), the annotation falls back to the whole file's last-touch date and says so.

**How to use this:** for each row, write a verdict in the blank "Muxin's ruling" column — e.g. "canvas" / "keep repo" / "neither, use: ..." — before any of this copy is ported. Rows are only included where canvas and repo **differ**, or where one side has no counterpart at all; identical strings are omitted entirely (no need to review those). Structure, layout, component names, and CSS classes are **out of scope** here — those come from the canvas regardless of copy rulings, per HANDOFF-EXACT-MATCH.md's "port it, don't reinterpret" mandate; this report is copy text only.

Sections follow HANDOFF-EXACT-MATCH.md §0's ordering. Money-gap has no recovered canvas source (see §11 below) and is excluded from the diff.
